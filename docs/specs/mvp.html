Tabane — エージェント監督特化ターミナル（MVP）

1画面をペイン分割して複数の Claude Code / codex / CLI を並べ、各ペインに自由入力タイトルを付け、返事待ちになったペインが光って分かる Electron アプリ。

ステータス：ドラフト 規模：中 対象：新規リポ（Electron デスクトップアプリ） 2026-07-15

1. 目的

複数の AI エージェント（Claude Code / codex）を並行で走らせると「どれが入力待ちか」を目視巡回する羽目になり、切り替えコストと見落としが発生する。既存ターミナル（Ghostty 等）はペインに恒常的なラベルを付けられず、返事待ちの可視化もない。「並べる・名札を付ける・待ちが光る」の3点に特化した監督用ターミナルを作り、複数エージェント運用の認知負荷を下げる。あわせて公開リポ + build in public でZenn記事・ポートフォリオ素材としても育てる。

2. スコープ

やること（MVP）
  • Electron + React + TypeScript + xterm.js + node-pty の土台（electron-vite）
  • ペインの分割（縦/横）・リサイズ・クローズ（1ウィンドウ内、Wave型レイアウト）
  • 各ペイン上部の固定タイトルバー（自由入力で編集可）
  • 各ペインで zsh を起動（そこから claude / codex を手で叩く）
  • 返事待ち検知：エージェントが入力待ちになったらタイトルバーが発光 + 未読バッジ。フォーカスしたら消灯
  • 日本語UI（メニュー・ラベル類。MVPはUI自体が少ない）
  • macOS（Apple Silicon）で動作。検証は起動→分割→claude起動→検知→消灯の手動動線
やらないこと（MVP では）
  • ブラウザ・ファイルビューア等のウィジェット（全部ターミナルでいい、が合意）
  • SSH / リモート接続・セッション永続化
  • タブ・複数ウィンドウ・ワークスペース
  • レイアウト・タイトルの保存/復元（v2）
  • yukisuna-brand テーマ適用・背景画像（v2。CSS 変数で差し込める作りにはしておく）
  • 設定GUI（v2。MVPは設定ファイル or ハードコード最小限）
  • Windows / Linux 対応（構成上は可能。動作確認を後回しにするだけ）
  • エージェントAPI連携・自動応答などターミナル外の機能

3. 処理フロー

起動（1ペイン）→ 分割操作でペイン追加→ ペインごとに node-pty で zsh 起動→ xterm.js に出力を流す→ main 側で PTY 出力を監視→ 「返事待ち」判定→ タイトルバー発光→ ペインフォーカスで消灯
why: 検知は「出力が止まった＝考え終わって入力待ちらしい」だけだと誤検知する（長考中も止まる）。そこで ①BEL（Claude Code の terminal bell 通知）/ OSC 9・777 通知シーケンスを一次シグナル、②出力静止タイマー（数秒）+ 直近出力の入力待ちプロンプトらしさを補助シグナルにする2段構え。判定ロジックは renderer でなく main プロセス側に置き、ペインが非表示でも検知が動くようにする。

4. アプローチ案（返事待ち検知）

案内容トレードオフ採否
ABEL / OSC 通知シーケンス + 出力静止タイマーのハイブリッド実装が素直で拡張しやすい。プロンプトパターン依存が薄い。静止タイマー単体の誤検知は BEL 優先で緩和推奨
B画面末尾のテキストをパターンマッチ（"❯" や "Do you want" 等）Claude Code の UI 変更に追従が必要で壊れやすい。多言語・codex 対応も個別対応になる—（補助シグナルとしてだけ利用）
Cプロセス状態（フォアグラウンドプロセスの CPU / read 待ち）を監視正確だが macOS 依存の低レベル実装になり MVP には重い—（v2以降の改善候補）
