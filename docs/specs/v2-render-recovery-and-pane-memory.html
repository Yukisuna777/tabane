Tabane v2 — 文字化け修正 / ペインごとの状態記憶

長時間起動すると全ペインが文字化けして読めなくなる不具合の修正と、ペインごとに「最後にいたフォルダ」「最後に見た Claude Code の resume コード」を覚えて再起動後に引き継ぐ機能。

ステータス：ドラフト（承認待ち） 規模：中 対象：既存リポ v0.1.1 2026-08-05

1. 目的

A：文字化け（バグ） — 数時間〜一晩置くと全ペインのテキストが別グリフに化け、スクロールバックごと読めなくなる。監督用ターミナルとして致命的（見張るための画面が見えない）。原因は特定済みで、xterm.js が公式に必須としているハンドリング漏れ。

B：ペインの状態記憶（機能） — レイアウトとタイトルは復元されるのに、シェルは毎回ホーム（または起動フォルダ）から始まり、Claude Code のセッションも辿れない。ペインの名札に対応する作業文脈（どこで・何の続きを）まで復元して、再起動のコストを消す。

2. 原因分析 — なぜ長時間で化けるのか

terminalRegistry.ts:155-159 で WebglAddon を読み込んでいるが、onContextLoss を購読していない。これが直接の原因。

  • WebGL コンテキストの喪失が復旧されない。 OS スリープ復帰・GPU プロセスのクラッシュ／再起動・ディスプレイ切替でコンテキストは失われる。xterm.js のドキュメントは「onContextLoss で addon を dispose() すること」を必須手順として明記している。購読していない現状では、死んだコンテキストに描き続け、画面はゴミのまま固定される。
  • テクスチャアトラスの破損。 xterm.js の型定義自身が clearTextureAtlas() の説明で「Chromium/Nvidia には OS スリープ復帰時にテクスチャが壊れる問題がある」と、まさにこの症状を書いている。グリフはアトラス（GPU 上のグリフ表）から座標参照で描かれるので、アトラスがずれると「別の文字に化ける」。スクショの症状（既に描画済みの行まで化け、直近の ASCII 行だけ正常）はこの座標ずれの典型。
  • 全ペインが同時に化ける理由。 アトラスは「同一フォント設定の端末間で共有」される。1枚壊れると共有している全ペインが道連れになる。スクショで7ペインすべてが化けているのはこれで説明がつく。
  • 長時間ほど起きやすい理由。 ①スリープ／ディスプレイ切替に遭遇する確率が上がる ②日本語・Powerline・罫線と使用グリフ種が増えアトラスのページが膨らむ ③分割とクローズを繰り返すぶん WebGL コンテキストが作られ、Chromium の上限（1レンダラあたり16前後）に触れると古いものから強制的に失われる。すべて「復旧経路が無い」という一点に収束する。
why: つまり「化けないようにする」のではなく 「化けたら必ず直る経路を作る」 のが正解。GPU コンテキストの喪失もアトラス破損も外部要因（OS・ドライバ）で必ず起きうるもので、こちらから防ぎきることはできない。復旧が自動で走れば、ユーザーから見た不具合は消える。

3. スコープ

やること
  • A-1：onContextLoss を購読し、addon 破棄 → 張り直し（上限つき、最終的に DOM レンダラへ縮退）
  • A-2：復旧の自動トリガ（ウィンドウ復帰・DPR 変化）で全端末のアトラスを clearTextureAtlas()
  • A-3：手動復旧「表示 > 画面を再描画」（Cmd+Shift+R）— 保険として残す
  • B-1：ペインごとの cwd 追跡（OSC 7 一次 + lsof ポーリング二次）と復元
  • B-2：PTY 出力から claude --resume <uuid> を検出して記憶
  • B-3：タイトルバーの resume チップ（クリックでコマンドを入力するだけ）
やらないこと
  • PTY / シェルセッションそのものの復元（プロセスは復元しない。cwd と入力補助まで）
  • スクロールバックの永続化（別件・容量が読めない）
  • claude --resume の自動実行（暴発が怖い。改行は送らない）
  • シェル履歴・環境変数の復元
  • WebGL をやめて DOM レンダラ固定にする（描画性能が落ちる。縮退先としてのみ使う）
  • codex 以外のエージェント固有 ID の対応（正規表現の追加で足りるので後追いでよい）

4. アプローチ案 — 文字化けの直し方

案内容トレードオフ採否
AonContextLoss で張り直し ＋ 復帰時アトラスクリア ＋ 手動再描画公式手順どおり。原因3系統（コンテキスト喪失・アトラス破損・上限超え）を全部拾える。追加依存なし推奨
BWebGL をやめて DOM レンダラ固定絶対に化けないが、多ペイン × 大量出力で描画が重くなる。tabane の用途（複数エージェント同時監視）と相性が悪い—（A の縮退先としてのみ）
C@xterm/addon-canvas を挟んで3段フォールバック依存が1つ増える。canvas レンダラも同じアトラス破損を持つので、根本対策にはならない見送り
D一定時間ごとに予防的にアトラスをクリア破損前に自動で戻せるが、再ラスタライズのわずかなカクつきが定期的に入る。A で足りるなら不要保留（A で残るようなら追加）

採用案の実装イメージ

// terminalRegistry.ts — WebGL は「壊れる前提」で張る
function loadWebgl(session: TermSession, attempt = 0): void {
  if (attempt > WEBGL_MAX_RETRY) return  // 諦めて DOM レンダラで走り続ける
  try {
    const addon = new WebglAddon()
    addon.onContextLoss(() => {
      addon.dispose()                       // 死んだコンテキストに描き続けさせない
      setTimeout(() => loadWebgl(session, attempt + 1), WEBGL_RELOAD_MS)
    })
    session.term.loadAddon(addon)
    session.webgl = addon
  } catch {
    // WebGL 不可の環境では DOM レンダラのまま
  }
}

/** 全端末のグリフキャッシュを捨てて描き直す（＝化けの手動/自動リセット）。 */
export function redrawAllTerminals(): void {
  for (const s of sessions.values()) s.term.clearTextureAtlas()
}

自動トリガは renderer 側に置く：window.focus / visibilitychange（スリープ・アプリ復帰）と、matchMedia(`(resolution: ${devicePixelRatio}dppx)`) の変化（外部ディスプレイ移動）。どちらも「化けが起きる瞬間」そのもので、ここでクリアすればユーザーは破損に気づかない。

5. 設計 — ペインごとの状態記憶

5.1 保存先

既存のレイアウト永続化にそのまま乗せる。PaneNode に2フィールド追加するだけで、config.json への保存・復元・debounce は既存経路を再利用できる。

export interface PaneNode {
  kind: 'pane'
  id: string
  title: string
  inheritCwdFromPtyId?: string
  /** 最後に観測した cwd。次回起動時の spawn cwd に使う。 */
  lastCwd?: string
  /** 最後に観測した再開コマンド（例 claude --resume <uuid>）。 */
  lastResume?: string
}

5.2 cwd の追跡（2段構え）

  • 一次：OSC 7（ESC]7;file://host/path BEL）。starship / oh-my-zsh 等を使っていればシェルが毎プロンプトで正確に報告してくれる。ptyManager の出力ハンドラで拾うだけなので追加コストはゼロ。
  • 二次：lsof ポーリング。既存の getCwdOfPid() をそのまま使う。macOS 素の zsh は OSC 7 を出さない（/etc/zshrc の報告は TERM_PROGRAM=Apple_Terminal 限定）ため、こちらが本命になる人も多い。出力があったセッションだけを10秒間隔で引く（dirty フラグ方式）。暇なペインでは lsof を起動しない。
  • 変化したときだけ pty:cwd を renderer に送る → PaneNode.lastCwd を更新 → 既存の debounce 保存に乗る。

5.3 resume コードの検出

Claude Code は終了時に次を出力する：

Resume this session with:
claude --resume cb9c8b81-1745-4961-82fa-c9c02be60cf8
  • PTY 出力から ANSI を剥がした末尾バッファ（512文字）に対して正規表現をかける。チャンク分割で UUID が割れても拾えるようにするため、バッファ方式は必須。
  • パターン：/claude\s+--resume\s+([0-9a-f-]{36})/i。codex 用に /codex\s+resume\s+(\S+)/i も同居させる（構造は同じなので追加コストなし）。
  • 検出したら pty:resume を renderer に送る。最後に見たものだけを保持（上書き）。

5.4 復元と UI

  • 起動時、attachTerminal に cwd を渡せるようにして createPty({ cwd: pane.lastCwd }) する。消えたディレクトリのフォールバックは ptyManager の既存チェック（existsSync）がすでに面倒を見ている。
  • lastResume があるペインは、タイトルバーに小さなチップ ⟲ resume を出す。クリックで端末にコマンドを入力するだけ（改行は送らない）。ユーザーが内容を見て Enter する。ホバーで完全な ID をツールチップ表示。
  • チップは新しい resume コードを観測したら黙って差し替わる。明示的な消去 UI は置かない（増やしすぎない）。
why: resume を自動実行しないのは、復元時に7ペインが一斉に Claude Code を起動して課金と混乱を生むのを避けるため。「名札」と同じで、tabane は文脈を提示するだけで、実行はユーザーが決める という一貫した立場を取る。

6. 処理フロー

A：文字化けからの復旧

スリープ復帰 / GPU クラッシュ→ コンテキスト喪失 or アトラス破損→ onContextLoss / focus / DPR 変化を検知→ addon 破棄 + 張り直し / アトラス clear→ 全グリフ再ラスタライズ→ 正常表示に復帰

B：ペイン状態の記憶と復元

PTY 出力→ OSC 7 / lsof で cwd、末尾バッファで resume を観測→ 変化時だけ renderer に通知→ PaneNode に書いて config.json に保存→ 次回起動でレイアウト復元→ lastCwd で spawn / resume チップ表示

8. 検証 — 完了の定義

  • npm run typecheck green
  • 文字化け（強制再現）：DevTools から WEBGL_lose_context 拡張でコンテキストを明示的に破棄 → 自動で描画が戻ること。戻らない場合も「画面を再描画」で必ず戻ること
  • 文字化け（実機）：Mac をスリープ→復帰、外部ディスプレイに移動、で化けないこと
  • cwd：ペインで cd → アプリ再起動 → 同じフォルダで開くこと。フォルダを削除してから再起動しても落ちずにホームへ落ちること
  • resume：Claude Code を起動→終了 → チップが出る → クリックでコマンドが入力される（実行はされない）→ 再起動後もチップが残ること
  • 非退行：分割・クローズ・リサイズで PTY が死なない（既存の永続化が壊れていない）、返事待ちの glow が従来どおり

9. 残論点 / 確認したいこと

  • プライバシー： config.json に作業フォルダのパスと Claude セッション ID が平文で残る。レイアウトとタイトルが既に残っているのと同程度だが、明示的に合意しておきたい。嫌なら設定で OFF にできるようにする
  • lsof のポーリング間隔： 10秒（出力のあったペインのみ）を提案。もっと粗くてよければ 30秒でも実用上は困らない
  • 予防的な定期アトラスクリア（案D）： まずは入れずに様子を見たい。それでも化けるようなら追加する
  • 再描画のショートカット： Cmd+Shift+R を提案。ブラウザの「スーパーリロード」と衝突しないか（Electron なので実害はないはず）
